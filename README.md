# Учёт показателей здоровья (Django + JSON/XML)

Django-приложение, которое позволяет:

1. **Вводить показатели здоровья через веб-форму** и сохранять их в файл
   **JSON или XML** (с валидацией всех полей).
2. **Загружать готовые файлы** JSON/XML на сервер с проверкой:
   - расширения и размера файла;
   - структуры и типов данных внутри файла, включая физиологические диапазоны;
   - при ошибке файл удаляется, а пользователю показывается причина.
3. **Просматривать содержимое всех файлов**, лежащих на сервере, в виде
   таблицы прямо в браузере. Если файлов нет — выводится сообщение об этом.

> Данные учебные/синтетические — приложение не предназначено для хранения
> реальных медицинских карт и не заменяет медицинскую информационную систему.

## Структура данных (вариант «Показатели здоровья», JSON/XML)

```json
{
  "records": [
    {
      "patient_full_name": "Мария Петрова",
      "birth_date": "1988-03-15",
      "blood_type": "O+",
      "height_cm": 165,
      "weight_kg": 60.5,
      "systolic_bp": 120,
      "diastolic_bp": 80,
      "heart_rate": 72,
      "temperature_c": 36.6,
      "measurement_date": "2024-01-10",
      "symptoms": ["Лёгкая усталость"]
    }
  ]
}
```

То же самое в XML:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<health_records>
  <record>
    <patient_full_name>Мария Петрова</patient_full_name>
    <birth_date>1988-03-15</birth_date>
    <blood_type>O+</blood_type>
    <height_cm>165</height_cm>
    <weight_kg>60.5</weight_kg>
    <systolic_bp>120</systolic_bp>
    <diastolic_bp>80</diastolic_bp>
    <heart_rate>72</heart_rate>
    <temperature_c>36.6</temperature_c>
    <measurement_date>2024-01-10</measurement_date>
    <symptoms>
      <symptom>Лёгкая усталость</symptom>
    </symptoms>
  </record>
</health_records>
```

## Правила валидации

- ФИО пациента — непустая строка из букв, пробелов и дефиса, до 100 символов.
- Дата рождения / дата измерения — формат `ГГГГ-ММ-ДД`, не в будущем; дата рождения не раньше 1900 года.
- Группа крови — одна из: `A+ A- B+ B- AB+ AB- O+ O-`.
- Рост — 50–250 см, вес — 2–300 кг.
- Давление — верхнее 60–250, нижнее 30–150, **и верхнее строго больше нижнего**.
- Пульс — 20–250 уд/мин, температура тела — 30–45 °C.
- Симптомы — список строк, не более 30 штук, каждая до 200 символов.

Границы — это не строгие клинические нормы (у разных людей "норма"
отличается), а разумные физиологически возможные пределы, отсекающие явный
мусор (например, пульс "9999" или отрицательный рост).

Эти же правила (`records/validators.py`) применяются **и** к форме, **и**
к содержимому загружаемых файлов — так поведение предсказуемо в обоих случаях.

## Безопасность загрузки файлов

- Разрешены только расширения `.json` / `.xml`, размер — до 2 МБ.
- **Имя файла на диске всегда генерируется сервером** (`uuid4` + метка времени),
  оригинальное имя от пользователя нигде не используется для записи на диск —
  это защищает от path traversal (`../../etc/passwd`) и переписывания чужих файлов.
- Файл сначала сохраняется, затем разбирается и валидируется; если он не
  соответствует структуре — удаляется, и пользователю показывается причина.
- XML от пользователя разбирается через `defusedxml`, а не «голый»
  `xml.etree.ElementTree`, — это защита от XML-бомб (billion laughs) и XXE.
- Папки с данными (`data_storage/json`, `data_storage/xml`) не отдаются
  сервером напрямую по URL — доступ к содержимому только через view-функции.

## Установка и запуск

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python manage.py migrate
python manage.py test records   # прогнать тесты (необязательно)
python manage.py runserver
```

Открыть в браузере: <http://127.0.0.1:8000/>

Разделы:
- `/` — главная
- `/create/` — ввод данных вручную
- `/upload/` — загрузка файла
- `/data/` — просмотр всех данных

## Структура проекта

```
healthdata/          # настройки Django-проекта
records/
  forms.py            # HealthRecordForm, UploadFileForm
  validators.py        # validate_record_dict — общая валидация
  utils.py             # генерация имён файлов, конвертация dict<->JSON/XML
  views.py             # create_record, upload_file, view_data, home
  templates/records/   # HTML-шаблоны (Bootstrap 5)
  tests.py             # тесты основных сценариев
data_storage/
  json/                # сюда сохраняются .json файлы
  xml/                 # сюда сохраняются .xml файлы
```
